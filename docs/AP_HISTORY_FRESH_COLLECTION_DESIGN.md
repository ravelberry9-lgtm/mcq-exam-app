# AP History fresh collection: design, learner switch (implemented locally) and local results

Basis: `AP_HISTORY_FRESH_BUILD_DECISION_20261009.txt` and `PRODUCTION_READONLY_FINDINGS_20261009.txt`. The old64-versus129 reconciliation is cancelled; legacy banks (including the older 64 that production holds) are not merged into the new collection. Nothing here touches production.

## 1. What "the new collection" is
Membership is the explicit column `collection_id` (value `ap-history-fresh-v1`) on `questions` and `expanded_notes`. NULL means the legacy bank. **Nothing else defines membership**: not `source` (`codex_generated` is also on older rows), not `syllabus_chapter_id` (older rows may carry one). Generic Practice banks, legacy `/practice/<slug>`, the legacy question counts on the canonical outline, duplicate scoping and the learner switch all key on `collection_id`. Fresh questions have no legacy `chapter_id`, so nothing in the legacy chapters, exam papers or progress tables is touched.
Limitation worth knowing: `expanded_notes` is unique on `(subject, anchor_id)`, so a second collection cannot reuse the same anchor ids; a v2 collection would need its own ids or a schema change.

## 2. Importer
`--collection-id` (default `ap-history-fresh-v1`, validated) stamps every imported row; `--overlap-scope collection` makes only rows with that collection id (or earlier rows in the same batch) able to block an apply; legacy overlaps are listed as informational and never modified. Default scope `all` and `--allow-overlaps` are unchanged. The notes loader stamps the same id and reports (never re-tags) existing notes with a different one. Add-only, one transaction, idempotent, `--approval-ref` required, notes before questions.

## 3. Learner switch (database setting, legacy default)
* **Tables** (migration `c9d0e1f2a3b4`, additive): `chapter_collection_setting` (one row per canonical chapter; absent or NULL = legacy) and `chapter_collection_log` (append-only: chapter slug, from, to, actor, remote address, time, readiness result, reason).
* **Identification**: by canonical chapter slug (`u1-c01-region-people-sources`), never by database id.
* **Readiness gate** (`app/services/collection_switch.py`), all must pass, no override: notes present and core; every note bilingual (heading and body); addendum connections resolve; every note page builds; questions present for the chapter; all `bilingual_approved`; stem, four options, answer and explanation in both languages; every question on a subtopic of this chapter; no legacy chapter id on collection rows; no duplicate stem or content hash inside the collection; every question names an expanded-note anchor and its note link resolves to a loaded note. Switching back to legacy is always allowed.
* **Admin only**: `/admin/collections` and `/admin/collections/switch` sit behind the existing admin PIN session and the app-wide CSRF check. The gate is a shared PIN, so "who" is the name typed on the form (required) plus the remote address, time and readiness result. A named-user login would be a larger change and is not part of this.
* **What learners see.** Legacy (default): the canonical chapter page shows the legacy entry; the fresh notes, practice and subtopic URLs return 404 for learners. Fresh: the chapter page shows the fresh notes and practice cards and no legacy entry; the outline shows the fresh question count. Administrators logged in can always preview an unswitched chapter (banner shown). Practice, notes and review links are consistent because a question's "Read this in notes" link is built from its own collection: fresh questions link to expanded-note anchors, legacy questions to legacy sections.
* **Switching back preserves everything.** A switch writes only the setting row and a log row. Tested row-for-row across four consecutive switches: every question and note of both collections, the legacy notes and every learner-state row are identical. Once a chapter has been switched to the collection, its pages stay reachable by URL afterwards, so a learner's saved review links and history never dead-end; they are no longer offered from the chapter page.
* **Not changed by the switch**: legacy practice, legacy `/learn/topic/...` pages, exam papers and sessions, progress, study plans, other subjects.

## 4. Local results
Tests: `tests/test_ap_v1_native.py` (43 tests, including the switch, each readiness failure, admin-only access, audit trail, switch-back preservation, collection-id duplicate scoping, and that older canonical-tagged rows stay in the legacy listings). Real-package run on isolated local PostgreSQL copies: all 12 readiness checks pass for 129 questions and 74 notes; switch to fresh, learner sees fresh pages; switch back, legacy entry returns; fingerprint over questions, notes and expanded notes identical before and after. A copy that holds the older 64 (given a canonical chapter id and `codex_generated`, the worst case): scope `all` refuses on 36 entries, scope `collection` imports 129 and reports the 36 (30 fresh questions against 30 older rows) as informational; the 64 older rows are unchanged and still served by legacy chapter practice.
